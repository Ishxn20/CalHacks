# Pile Identification + Pick Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** From a voice-resolved instrument id, find the instrument in a cluttered pile with a trained segmentation model, uncover it if buried, and pick it with the existing B601-RS arm stack.

**Architecture:** Three packages in one repo. `arm/scrub_arm` (existing) gains inverse kinematics, a contact-sensing `_pick_at`, and a declutter loop that asks a perception HTTP service what to do next. `perception/scrub_vision` (new) owns the camera, a YOLO11-seg model, classical length/template identification on top of the masks, and the `/plan` `/verify` `/debug` endpoints. `sim/` (new) is a MuJoCo pile generator that produces physically settled poses rendered by the same rasteriser as the random-placement generator, so both write the same dataset.

**Tech Stack:** Python 3.12 (pyenv), pinocchio (`pin`), numpy, opencv-python, trimesh, ultralytics, mujoco, pyyaml, pytest. Existing: motorbridge, faster-whisper.

**Spec:** `docs/superpowers/specs/2026-10-23-surgical-tool-arm-design.md`

## Global Constraints

- Python >= 3.10 (repo), use 3.12 locally. Arm package deps stay `numpy, pyyaml` + optional `[kinematics]` extra `pin`; no ultralytics/opencv in `arm/`.
- `pick_mode: slots` must keep all existing `arm/tests` passing unchanged.
- Units: arm code radians/metres internally; HTTP and YAML in degrees/millimetres (matches existing `arm.yaml` style).
- Instrument ids are the keys in repo-root `config/tray.yaml` `instruments`. Coarse classes (10): `clamp_cross, clamp_satinsky, castroviejo, ring_needle_holder, potts, micro_scissors_fwd, micro_scissors_back, forceps, scalpel` (+ `probe` reserved, unused).
- Fine-identity length tolerance ±8 %. Declutter cap 6 moves. Hover 80 mm. Contact threshold default 1.5°. Gripper mask bottom 25 % of frame.
- Never move the real arm from a test. All tests run with `SimBus`/fakes.
- Commits: conventional prefixes, each task one commit. Branch `pile-pick`.

## Review Focus

1. Instrument lying flipped (mirror silhouette) must still get the right class and a grasp point at the tip end. Test in Task 9.
2. Two forceps of different lengths touching end to end could merge into one long blob under HSV fallback; the length gate must reject (no class within ±8 %) rather than mis-classify. Test in Task 9.
3. `/plan` unreachable or returning malformed JSON must fail the job with a spoken message, never raise through the server. Test in Task 5.
4. IK target outside reach or outside joint limits must return `None` and the job must not move the arm at all. Test in Tasks 2 and 4.
5. Contact detected on the first descent step (instrument higher than expected) must stop without descending further and still attempt the grasp. Test in Task 4.

### Task 2: Kinematics wrapper

**Interfaces:**
- Produces: `class Kinematics(urdf_path: Path | None = None, tool_frame: str = "gripper_end")`

  - `ik_topdown(x: float, y: float, z: float, yaw: float, q_seed: np.ndarray, limits: tuple[np.ndarray, np.ndarray]) -> np.ndarray | None` metres/radians; tool axis (link6 local z, i.e. the direction from `link6` to `gripper_end`) aligned to world −z, jaw axis rotated by `yaw` about world z; damped least squares on `pin.log6` error, 200 iters, damping 1e-4, step 0.5; returns None if final position error > 2 mm or any joint outside `limits`. Tries `yaw` and `yaw+π`, returns the solution nearest `q_seed`.
  - `jaw_axis_local: np.ndarray` = unit vector in `tool_frame` along which the fingers separate (read from the two prismatic joints' axes in the URDF).
